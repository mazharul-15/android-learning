# Android `R` Class — Complete Notes

## 1. What is the `R` class?

`R` is a generated Android class that gives your Kotlin/Java code access to resources inside the `res/` folder.

Think of it as a bridge:

```text
res/
│
├── drawable/
├── layout/
├── mipmap/
└── values/
       │
       ↓
   Generated R class
       │
       ↓
Kotlin / Java code
```

For example:

```kotlin
R.layout.activity_main
R.id.btnLogin
R.drawable.logo
R.string.app_name
R.color.blue
```

You normally do not write the `R` class yourself. Android Gradle tooling generates it from your project resources.

---

# 2. Why do we need `R`?

Suppose you have:

```text
res/layout/activity_main.xml
```

Kotlin can refer to that layout as:

```kotlin
R.layout.activity_main
```

Suppose you have:

```text
res/drawable/logo.png
```

Kotlin can refer to it as:

```kotlin
R.drawable.logo
```

So instead of working directly with file paths, Android gives resources generated IDs through `R`.

---

# 3. Basic Structure

You can think of `R` like this:

```text
R
│
├── id
├── layout
├── drawable
├── mipmap
├── string
├── color
├── dimen
├── style
└── ...
```

Each section corresponds to a resource type.

Example:

```kotlin
R.id.btnLogin
```

means:

```text
R
 ↓
id
 ↓
btnLogin
```

And:

```kotlin
R.layout.activity_main
```

means:

```text
R
 ↓
layout
 ↓
activity_main
```

# 4. `R.layout`

Used to reference XML layouts.

If you have:

```text
res/layout/activity_main.xml
```

use:

```kotlin
R.layout.activity_main
```

Example:

```kotlin
setContentView(R.layout.activity_main)
```

With View Binding, you usually do not need to reference the layout this way for `setContentView()`:

```kotlin
binding = ActivityMainBinding.inflate(layoutInflater)
setContentView(binding.root)
```

But `R.layout` is still important to understand.

---

# 5. `R.id`

Used to reference View IDs.

XML:

```xml
<Button
    android:id="@+id/btnLogin"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="Login" />
```

Kotlin can reference the ID:

```kotlin
R.id.btnLogin
```

Traditional `findViewById()`:

```kotlin
val btnLogin = findViewById<Button>(R.id.btnLogin)
```

With View Binding:

```kotlin
binding.btnLogin
```

View Binding uses the same underlying resource IDs, but gives you a safer and more convenient API.

---

# 6. `R.drawable`

References resources inside `res/drawable/`.

Example:

```text
res/drawable/logo.png
```

Use:

```kotlin
R.drawable.logo
```

Example:

```kotlin
binding.ivLogo.setImageResource(R.drawable.logo)
```

XML:

```xml
android:src="@drawable/logo"
```

---

# 7. `R.mipmap`

References launcher/app icon resources.

Example:

```text
res/mipmap-xxxhdpi/ic_launcher.png
```

Use:

```kotlin
R.mipmap.ic_launcher
```

The manifest commonly contains:

```xml
android:icon="@mipmap/ic_launcher"
```

Remember:

```text
drawable → normal app images/drawables
mipmap   → launcher/app icons
```

---

# 8. `R.string`

References strings from `strings.xml`.

Example:

```xml
<!-- res/values/strings.xml -->

<resources>
    <string name="app_name">Student Manager</string>
    <string name="login">Login</string>
</resources>
```

Kotlin:

```kotlin
val title = getString(R.string.app_name)
```

XML:

```xml
android:text="@string/login"
```

This is better than hardcoding the same text everywhere.

---

# 9. `R.color`

References colors defined in `colors.xml`.

Example:

```xml
<color name="blue">#2196F3</color>
```

Kotlin:

```kotlin
val color = ContextCompat.getColor(
    this,
    R.color.blue
)
```

XML:

```xml
android:textColor="@color/blue"
```

---

# 10. `R.dimen`

References dimensions from `dimens.xml`.

Example:

```xml
<dimen name="screen_padding">16dp</dimen>
```

XML:

```xml
android:padding="@dimen/screen_padding"
```

Kotlin:

```kotlin
val padding = resources.getDimension(R.dimen.screen_padding)
```

Note that `getDimension()` returns the converted pixel size as a `Float`.

---

# 11. `R.style`

References styles/themes where applicable.

Example:

```xml
<style name="StudentTitle">
    <item name="android:textSize">24sp</item>
    <item name="android:textStyle">bold</item>
</style>
```

Use:

```xml
style="@style/StudentTitle"
```

Theme resources are also represented through generated `R` resources.

---

# 12. `R` and XML `@`

There are two common ways to reference resources.

## In XML

Use:

```xml
@string/app_name
@drawable/logo
@color/blue
@layout/activity_main
@id/btnLogin
```

## In Kotlin

Use:

```kotlin
R.string.app_name
R.drawable.logo
R.color.blue
R.layout.activity_main
R.id.btnLogin
```

Think:

```text
XML:
@drawable/logo

Kotlin:
R.drawable.logo
```

---

# 13. `@+id` vs `@id`

This is very important.

When creating a new ID:

```xml
android:id="@+id/btnLogin"
```

`+` means:

> Create this ID if it does not already exist.

After the ID exists, reference it with:

```xml
@id/btnLogin
```

Example:

```xml
<Button
    android:id="@+id/btnLogin"
    ... />

<TextView
    ...
    app:layout_constraintStart_toEndOf="@id/btnLogin" />
```

In Kotlin:

```kotlin
R.id.btnLogin
```

---

# 14. `R.id` and ConstraintLayout

Suppose:

```xml
<TextView
    android:id="@+id/tvTitle"
    ... />
```

Another View can reference it:

```xml
app:layout_constraintTop_toBottomOf="@id/tvTitle"
```

The generated resource is:

```kotlin
R.id.tvTitle
```

So:

```text
tvTitle
   ↓
@id/tvTitle in XML
   ↓
R.id.tvTitle in Kotlin
```

---

# 15. `R` and View Binding

You have learned View Binding, so this distinction is important.

Without View Binding:

```kotlin
val button = findViewById<Button>(R.id.btnLogin)

button.setOnClickListener {
    ...
}
```

With View Binding:

```kotlin
binding.btnLogin.setOnClickListener {
    ...
}
```

Why?

View Binding generates a binding class from the layout and gives you direct references to Views.

Example:

```text
activity_main.xml
      ↓
ActivityMainBinding
      ↓
binding.btnLogin
binding.tvTitle
binding.etEmail
```

So you will use `R` less for direct View access, but `R` remains fundamental for other resources.

# 16. `R.string` with Kotlin

Suppose:

```xml
<string name="welcome">Welcome</string>
```

Instead of:

```kotlin
binding.tvWelcome.text = "Welcome"
```

you can use:

```kotlin
binding.tvWelcome.text = getString(R.string.welcome)
```

Why?

Because the text is stored as a resource.

# 19. `R` Is Generated

You should not create:

```text
R.kt
R.java
```

yourself.

Android generates the resource class based on your resources.

For example:

```text
res/
├── drawable/logo.png
├── layout/activity_main.xml
└── values/strings.xml
```

results conceptually in:

```text
R.drawable.logo
R.layout.activity_main
R.string.app_name
```

The generated implementation details are handled by Android's build system.

# 20. What Happens When You Add a Resource?

Suppose you add:

```text
res/drawable/profile.png
```

Android's resource processing detects it.

You can then use:

```kotlin
R.drawable.profile
```

Similarly, if you create:

```xml
<string name="student_name">Abir</string>
```

you can use:

```kotlin
R.string.student_name
```

Think:

```text
Add resource
     ↓
Android build system processes it
     ↓
Resource ID generated
     ↓
R gives your code access
```

# 21. What Happens When `R` Has an Error?

Sometimes Android Studio shows:

```text
Unresolved reference: R
```

or resources appear unavailable.

Common causes include:

```text
1. XML resource has an error
2. Gradle/build problem
3. Wrong package/import
4. Resource naming is invalid
5. Project has not successfully built/synced
```

First check your XML files for errors.

For example, an invalid resource name such as:

```text
Student Image.png
```

can cause problems.

Prefer:

```text
student_image.png
```

---

# 22. Wrong `R` Import

In an Android app module, Android Studio normally resolves your app's generated `R` class automatically.

If you accidentally import another module/library's `R`, you can get confusing errors.

For example, be careful with imports such as:

```kotlin
import android.R
```

`android.R` refers to **Android framework resources**, not your application's resources.

Your application normally uses its own generated `R`.

---

# 23. `android.R` vs Your App's `R`

This is a common beginner confusion.

### `android.R`

Contains resources provided by the Android framework.

Example:

```kotlin
android.R.id.content
```

### Your app's `R`

Contains resources from your app:

```kotlin
R.id.btnLogin
R.string.app_name
R.drawable.logo
```

Simple rule:

```text
android.R
   ↓
Android framework resources

R
   ↓
Your application's resources
```

---

# 24. `R` Does Not Store the Actual Image/Text

This is an important mental model.

`R.drawable.logo` is **not the image itself**.

It is a generated resource identifier/reference that Android uses to locate the resource.

Similarly:

```kotlin
R.string.app_name
```

is not the actual `"Student Manager"` String object.

It identifies the string resource.

Think:

```text
R.drawable.logo
       ↓
"Which drawable resource?"

R.string.app_name
       ↓
"Which string resource?"
```

---

# 25. Resource ID Concept

Conceptually, Android associates resources with generated identifiers.

You might see values represented internally as integer resource IDs.

You normally should **not depend on the exact numeric value**.

Use:

```kotlin
R.id.btnLogin
```

rather than trying to manually manage resource numbers.
