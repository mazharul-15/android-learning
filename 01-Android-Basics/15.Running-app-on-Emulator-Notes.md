# Running app on Emulator — Android Notes

## What is an Android Emulator?

An Android Emulator is a virtual Android device running on your computer. It lets you test an Android app without a physical phone.

```text
Computer
   |
Android Studio
   |
Android Emulator
   |
Your App
```

## What is an AVD?

AVD means **Android Virtual Device**. It is the configuration of a virtual Android device.

An AVD includes things such as:

- Device model
- Android version/system image
- Screen size
- Hardware configuration
- Storage

```text
AVD = configuration
Emulator = runs that virtual device
```

## Create an Emulator

In Android Studio:

```text
Tools
  ↓
Device Manager
  ↓
Create Device
  ↓
Choose a phone
  ↓
Choose a system image
  ↓
Download image if necessary
  ↓
Next
  ↓
Finish
```

Android's official documentation describes creating and managing AVDs in Device Manager.

## Start the Emulator

Open:

```text
Tools → Device Manager
```

Find your AVD and click the **Launch/Play** button.

Wait for Android to boot and show the home screen.

## Run Your App

1. Open your Android project.
2. Start the emulator.
3. In Android Studio's device selector, select the emulator.
4. Click **Run ▶**.

Conceptually:

```text
Click Run
   ↓
Build project
   ↓
Create debug app package
   ↓
Install app on emulator
   ↓
Launch app
```

Android Studio's Android App run configuration supports an Emulator as a deployment target.

## Emulator Is Not Your Project

You do not create a separate project for the emulator.

```text
StudentApp
   |
   +-- Run on Emulator
   |
   +-- Run on Physical Phone
   |
   +-- Run on another device
```

The emulator is simply a device used to run your project.

## Why Use an Emulator?

The emulator is useful for:

- Learning Android
- Testing XML layouts
- Testing different screen sizes
- Testing different Android versions
- Testing ConstraintLayout
- Testing ScrollView
- Testing RecyclerView
- Testing Activity navigation
- Debugging

It is especially useful when you are developing your Login, Registration, Student Info, News, Notes, and Weather projects.

## Testing Different Screen Sizes

One major advantage is that you can create different virtual devices.

```text
Phone
Tablet
Foldable
```

This helps you check whether your responsive XML works correctly.

For example:

```text
Small phone
    ↓
Does UI fit?

Large phone
    ↓
Does UI still look good?

Tablet
    ↓
Does UI adapt?
```

## Emulator and ConstraintLayout

The emulator is useful for checking:

- Views are centered correctly
- Guidelines are positioned correctly
- Chains behave correctly
- Barriers work correctly
- Views do not overlap
- Layouts adapt to screen sizes

For example:

```xml
app:layout_constraintStart_toStartOf="parent"
app:layout_constraintEnd_toEndOf="parent"
```

Run the app and check the result on the emulator.

## Emulator and Logcat

Your Kotlin code can write logs:

```kotlin
Log.d("Student", "Student added")
```

When the app is running:

```text
D/Student: Student added
```

appears in Logcat.

So:

```text
App
 ↓
Emulator
 ↓
Logcat
 ↓
Developer observes/debugs
```

## Run vs Debug

### Run

Runs the application normally.

### Debug

Runs the app with Android Studio's debugging tools available.

Conceptually:

```text
Run
 ↓
App executes

Debug
 ↓
App executes
 +
Inspect/debug code
```

## If the Emulator Does Not Start

Check:

1. Open **Tools → Device Manager**.
2. Make sure the AVD exists.
3. Try launching it again.
4. Check that the system image is installed.
5. Check available RAM and storage.
6. Restart Android Studio if necessary.

Device Manager also provides options such as:

```text
Stop
Edit
Wipe Data
Delete
```

## Wipe Emulator Data

If an emulator behaves strangely, Device Manager can provide **Wipe Data**.

```text
Existing emulator
       ↓
   Wipe Data
       ↓
Fresh user-data state
```

This removes the emulator's stored user data and app state, so use it when appropriate.

## Emulator Is Slow

Emulators use significant computer resources.

If yours is slow:

- Close unnecessary applications.
- Check available RAM.
- Make sure hardware virtualization is available/enabled.
- Avoid running many emulators simultaneously.
- Use a suitable system image.
- Use a physical device if your computer cannot comfortably run an emulator.

## Multiple Emulators

You can create multiple AVDs:

```text
Pixel-Phone
Pixel-Large
Tablet
```

Then test:

```text
Your App
   |
   +-- Pixel-Phone
   +-- Pixel-Large
   +-- Tablet
```

You do not need many emulators while learning.

## Emulator vs Physical Device

| Feature | Emulator | Physical Device |
|---|---|---|
| Real phone required | No | Yes |
| USB cable | No | Usually |
| Developer Options | No | Yes |
| USB debugging | No | Yes |
| Different screen sizes | Excellent | Limited |
| Different Android versions | Easy | Limited |
| Real hardware behavior | Not exact | Yes |
| Camera/sensors | Simulated/limited | Real |
| Computer resources | Higher | Lower |

The Emulator is useful for testing different Android versions and screen sizes; Android also recommends testing on a real device before release.

## Common Beginner Mistake

Do not think:

> "I need to put my project inside the emulator."

You don't.

Android Studio builds and installs your app on the emulator.

```text
Your project
     ↓
Android Studio builds it
     ↓
App package
     ↓
Emulator
```
