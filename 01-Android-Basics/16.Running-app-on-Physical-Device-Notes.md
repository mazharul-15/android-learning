# Running App on a Physical Android Device

## 1. What Does It Mean?

You can run the same Android Studio project directly on a real Android phone.

```text
Android Studio
      |
      | USB / Wi-Fi debugging
      ↓
Physical Android Phone
      |
      ↓
Your App
```

Android recommends testing apps on a real device before release. citeturn0search0

---

## 2. What You Need

You generally need:

- Android Studio
- An Android phone
- A USB data cable, or supported wireless debugging
- Developer Options enabled
- USB debugging enabled for USB connection

On Windows, an appropriate OEM USB driver may be required for some devices. citeturn0search0

---

## 3. Enable Developer Options

On your phone:

```text
Settings
   ↓
About phone
   ↓
Build number
```

Tap **Build number** several times (commonly 7 times).

Android then enables the Developer Options menu. The exact location/name can vary by manufacturer. citeturn0search3

---

## 4. Enable USB Debugging

Open:

```text
Settings
   ↓
Developer options
   ↓
USB debugging
```

Turn it on.

USB debugging allows Android Studio and ADB to communicate with your phone. citeturn0search3

---

## 5. Connect the Phone Using USB

Connect your phone to the computer using a USB cable.

Make sure the cable supports **data transfer**, not only charging.

Your phone may display:

```text
Allow USB debugging?
```

If you trust this computer, tap:

```text
Allow
```

Android uses an RSA authorization prompt to protect the device from unauthorized ADB connections. citeturn0search0

---

## 6. Select the Physical Device

Open your Android project.

In Android Studio's device selector, your phone should appear.

For example:

```text
app ▼

Pixel / Samsung / Xiaomi ...
```

Select your physical phone.

Then click:

```text
Run ▶
```

Android Studio builds the app, installs it on the selected device, and launches it. citeturn0search0turn0search5

---

## 8. What Is ADB?

ADB means:

```text
Android Debug Bridge
```

It is the communication bridge between your computer and Android device.

```text
Android Studio
      ↓
     ADB
      ↓
Android Phone
```

ADB is used for tasks such as:

- Installing an app
- Running/debugging an app
- Checking connected devices
- Communicating with the device

---

## 9. Check the Device with ADB

You can verify a USB-connected device with:

```bash
adb devices
```

If the phone is connected and authorized, it should appear in the output. Android's official documentation specifically recommends `adb devices` for verifying the connection. citeturn0search0

Conceptually:

```text
adb devices
     ↓
Connected devices
     ↓
Your phone
```

You do not need to use ADB commands every day while learning Android Studio.

---

## 10. USB Mode

When you connect the phone, Android may show USB connection options.

If available, choose a mode such as:

```text
File Transfer
```

instead of only:

```text
Charge only
```

The exact options depend on the phone.

## 12. Physical Device + Logcat

Suppose you write:

```kotlin
Log.d("StudentInfo", "Student ID = $studentId")
```

Run the app on your phone.

Android Studio Logcat can show:

```text
D/StudentInfo: Student ID = 1502055
```

So:

```text
Physical Phone
      ↓
Running App
      ↓
Logcat
      ↓
Debugging
```

## 13. Physical Device + Debug Mode

You can also debug your app on the physical device.

Basic workflow:

```text
Set breakpoint
      ↓
Select physical device
      ↓
Click Debug
      ↓
App runs
      ↓
Inspect variables
      ↓
Step through code
```

Android Studio supports breakpoints, variable inspection, and runtime debugging on connected devices. citeturn0search4

---

## 14. Physical Device + Layout Inspector

Android Studio's Layout Inspector can inspect a running app on a physical device.

It can help you inspect:

```text
View hierarchy
View attributes
Layout structure
```

This is useful when your XML layout does not behave as expected. citeturn0search2

---

## 15. USB vs Wi-Fi Debugging

You can connect a physical Android device using:

```text
USB
```

or, on supported Android versions:

```text
Wi-Fi / Wireless debugging
```

Android 11 and higher support wireless debugging through ADB. citeturn0search0

For your current learning, start with:

```text
USB
```

It is simpler for understanding the basic workflow.

---

## 16. Wireless Debugging

For supported devices:

```text
Phone
   ↓
Developer Options
   ↓
Wireless debugging
```

Your computer and phone should be on the same Wi-Fi network.

In Android Studio you can use:

```text
Pair Devices Using Wi-Fi
```

and pair using a QR code or pairing code. citeturn0search0

You can learn this after you are comfortable with USB debugging.

---

## 17. Phone Is Not Showing in Android Studio

Check these in order:

```text
1. Is USB debugging ON?
2. Is the USB cable a data cable?
3. Is the phone unlocked?
4. Did you allow USB debugging?
5. Is the phone using an appropriate USB connection mode?
6. Does the device appear in adb devices?
7. Does Windows need an OEM USB driver?
```

Android's Connection Assistant can also help troubleshoot device connections. citeturn0search0

---

## 18. Use Connection Assistant

If Android Studio does not detect your phone:

```text
Tools
   ↓
Troubleshoot Device Connections
```

The Connection Assistant can help with:

- USB connection
- USB debugging
- Rescanning USB devices
- Restarting the ADB server

citeturn0search0

---

## 19. Common Problem: Device Offline

If ADB reports the phone as:

```text
offline
```

try:

```text
Disconnect phone
      ↓
Reconnect phone
      ↓
Unlock phone
      ↓
Accept USB debugging prompt
```

If necessary, use Android Studio's Connection Assistant or restart the ADB server. citeturn0search0

---

## 20. Common Problem: Unauthorized

If the device appears unauthorized:

```text
Look at phone
      ↓
Allow USB debugging?
      ↓
Tap Allow
```

Make sure the phone is unlocked when the authorization dialog appears.

---

## 21. Common Problem: Cable

A charging-only cable may not provide the data connection required for ADB.

Try:

```text
Another USB cable
```

Android's official troubleshooting guidance also recommends checking the USB cable when a device is not detected. citeturn0search0

---

## 22. Windows USB Driver

On Windows, some Android devices may require an appropriate USB driver for ADB communication.

If your phone is not detected:

```text
Check your phone manufacturer's
OEM USB driver requirements
```

Android provides links/instructions for OEM USB drivers. citeturn0search0

---

## 23. Physical Device vs Emulator

| Feature | Physical Device | Emulator |
|---|---|---|
| Real phone | Yes | No |
| USB debugging | Yes | Not required |
| Real hardware | Yes | Simulated |
| Real camera | Yes | Simulated/virtual |
| Real sensors | Yes | Simulated/limited |
| Different screen sizes | Limited | Excellent |
| Different Android versions | Limited | Easy |
| Uses computer resources | Lower | Higher |
| Real performance | Yes | Not exact |

Use both during Android development.

## 26. Important: Same Project

Do not create separate projects for:

```text
StudentInfo-Emulator
StudentInfo-Phone
```

You only need:

```text
StudentInfo
```

The same project can run on:

```text
StudentInfo
    ↓
    ├── Emulator
    └── Physical Device
```
