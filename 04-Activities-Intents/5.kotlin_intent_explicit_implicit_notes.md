# Android Intent in Kotlin — Explicit and Implicit Intents

## 1. What is an Intent?

An **Intent** is a messaging object used by Android to request an action from another app component.

Common uses include:

- Starting another Activity
- Starting a Service
- Sending a broadcast
- Passing data between Activities
- Opening another app
- Sharing text or files
- Opening a web page, map, dialer, email app, etc.

Android has two primary types:

1. **Explicit Intent**
2. **Implicit Intent**

---

# 2. Explicit Intent

An **Explicit Intent** specifies the exact component that Android should start.

It is commonly used when moving between Activities inside your own application.

### Basic syntax

```kotlin
val intent = Intent(this, SecondActivity::class.java)
startActivity(intent)
```

Here:

- `this` is the current Activity context.
- `SecondActivity::class.java` identifies the exact Activity.
- Android does not need to search for another component.

---

# 3. Explicit Intent Example

Suppose an app has:

```text
MainActivity
SecondActivity
```

From `MainActivity`:

```kotlin
val intent = Intent(this, SecondActivity::class.java)
startActivity(intent)
```

Complete example:

```kotlin
class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        setContentView(R.layout.activity_main)

        val button = findViewById<Button>(R.id.openButton)

        button.setOnClickListener {
            val intent = Intent(this, SecondActivity::class.java)
            startActivity(intent)
        }
    }
}
```

---

# 4. Passing Data with an Explicit Intent

You can attach extra data to an Intent using `putExtra()`.

### Sending data

```kotlin
val intent = Intent(this, SecondActivity::class.java)

intent.putExtra("username", "Jammer")
intent.putExtra("age", 25)

startActivity(intent)
```

You can also use `apply`:

```kotlin
val intent = Intent(this, SecondActivity::class.java).apply {
    putExtra("username", "Jammer")
    putExtra("age", 25)
}

startActivity(intent)
```

---

# 5. Receiving Data in Another Activity

In `SecondActivity`:

```kotlin
class SecondActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        setContentView(R.layout.activity_second)

        val username = intent.getStringExtra("username")
        val age = intent.getIntExtra("age", 0)

        Log.d("IntentData", "Username: $username")
        Log.d("IntentData", "Age: $age")
    }
}
```

The receiving Activity can access the Intent through the Activity's `intent` property.

---

# 6. Recommended: Use Constants for Extra Keys

Instead of repeatedly writing string keys:

```kotlin
putExtra("username", "Jammer")
```

define constants:

```kotlin
const val EXTRA_USERNAME = "extra_username"
```

Then:

```kotlin
val intent = Intent(this, SecondActivity::class.java).apply {
    putExtra(EXTRA_USERNAME, "Jammer")
}

startActivity(intent)
```

Receiving:

```kotlin
val username = intent.getStringExtra(EXTRA_USERNAME)
```

This reduces spelling mistakes.

---

# 7. Passing Multiple Data Types

Intent extras can contain many supported types.

### String

```kotlin
intent.putExtra("name", "Jammer")
```

### Int

```kotlin
intent.putExtra("age", 25)
```

### Boolean

```kotlin
intent.putExtra("isLoggedIn", true)
```

### Double

```kotlin
intent.putExtra("price", 99.99)
```

### Long

```kotlin
intent.putExtra("timestamp", System.currentTimeMillis())
```

For objects, use appropriate supported mechanisms such as `Parcelable`.

# 8. Implicit Intent

An **Implicit Intent** does not specify an exact component.

Instead, it describes an action that should be performed.

Android looks for an Activity or other component capable of handling that action.

Example:

```kotlin
val intent = Intent(Intent.ACTION_VIEW).apply {
    data = Uri.parse("https://developer.android.com")
}

startActivity(intent)
```

Android can choose a suitable browser or another application that handles the URL.

---

# 9. Implicit Intent Example — Open Website

```kotlin
val intent = Intent(
    Intent.ACTION_VIEW,
    Uri.parse("https://developer.android.com")
)

if (intent.resolveActivity(packageManager) != null) {
    startActivity(intent)
}
```

`resolveActivity()` checks whether there is an Activity available to handle the Intent.

This is useful because an implicit Intent may have no matching application on the device.

---

# 10. Implicit Intent — Open Dialer

To open the phone dialer:

```kotlin
val intent = Intent(Intent.ACTION_DIAL).apply {
    data = Uri.parse("tel:0123456789")
}

if (intent.resolveActivity(packageManager) != null) {
    startActivity(intent)
}
```

`ACTION_DIAL` normally opens the dialer with the number ready.

---

# 11. Implicit Intent — Send Email

A simple email Intent can be created with `ACTION_SENDTO`.

```kotlin
val intent = Intent(Intent.ACTION_SENDTO).apply {
    data = Uri.parse("mailto:example@gmail.com")
    putExtra(Intent.EXTRA_SUBJECT, "Hello")
    putExtra(Intent.EXTRA_TEXT, "This is a test email.")
}

if (intent.resolveActivity(packageManager) != null) {
    startActivity(intent)
}
```

Using `mailto:` helps target email applications.

---

# 12. Implicit Intent — Open Map

```kotlin
val intent = Intent(
    Intent.ACTION_VIEW,
    Uri.parse("geo:23.8103,90.4125")
)

if (intent.resolveActivity(packageManager) != null) {
    startActivity(intent)
}
```

The system can choose an installed map application capable of handling the Intent.

---

# 13. Implicit Intent — Share Text

Use `ACTION_SEND` to share content.

```kotlin
val sendIntent = Intent().apply {
    action = Intent.ACTION_SEND
    putExtra(Intent.EXTRA_TEXT, "Hello from my Android app!")
    type = "text/plain"
}

if (sendIntent.resolveActivity(packageManager) != null) {
    startActivity(sendIntent)
}
```

For a better sharing experience, use the Android Sharesheet:

```kotlin
val shareIntent = Intent.createChooser(sendIntent, "Share using")

startActivity(shareIntent)
```

# 14. Explicit vs Implicit Intent

| Feature | Explicit Intent | Implicit Intent |
|---|---|---|
| Target | Exact component | General action |
| Component name | Specified | Not specified |
| Common use | Inside your app | Cross-app interaction |
| System searches for handler | No | Yes |
| Intent filter required | No for target matching | Usually yes for receiving |
| Example | `Intent(this, SecondActivity::class.java)` | `Intent(Intent.ACTION_VIEW, uri)` |

---

# 15. Easy Difference

### Explicit

You tell Android:

```text
"Open this exact Activity."
```

Example:

```kotlin
Intent(this, SecondActivity::class.java)
```

### Implicit

You tell Android:

```text
"Perform this action."
```

Example:

```kotlin
Intent(Intent.ACTION_VIEW, Uri.parse("https://example.com"))
```

Android finds an appropriate component.

# 16. Intent Filters

An **Intent Filter** tells Android which implicit Intents an Activity, Service, or BroadcastReceiver can respond to.

Intent filters are declared in `AndroidManifest.xml`.

Example:

```xml
<activity
    android:name=".ShareActivity"
    android:exported="false">

    <intent-filter>

        <action android:name="android.intent.action.SEND" />

        <category
            android:name="android.intent.category.DEFAULT" />

        <data android:mimeType="text/plain" />

    </intent-filter>

</activity>
```

This advertises that the Activity can handle text-sharing Intents.

---

# 17. Important Intent Filter Components

An Intent Filter can contain:

### `<action>`

Describes what action the component can perform.

Example:

```xml
<action android:name="android.intent.action.VIEW" />
```

### `<category>`

Provides additional information about the type of Intent.

Example:

```xml
<category android:name="android.intent.category.DEFAULT" />
```

### `<data>`

Describes the data type or URI the component can handle.

Example:

```xml
<data android:mimeType="text/plain" />
```

---

# 18. How Implicit Intent Resolution Works

When an implicit Intent is sent, Android compares it against available Intent Filters.

The system considers:

```text
Action
   +
Data / MIME type
   +
Category
```

If a matching component is found, Android can launch it.

If multiple components can handle the Intent, Android may allow the user to choose an application.

---

# 19. `CATEGORY_DEFAULT`

Activities that receive implicit Intents through `startActivity()` generally need:

```xml
<category android:name="android.intent.category.DEFAULT" />
```

Without the default category, the Activity will not normally resolve for implicit `startActivity()` calls.

---

# 20. `android:exported`

When an Activity has an Intent Filter, explicitly declare `android:exported`.

Example:

```xml
<activity
    android:name=".ShareActivity"
    android:exported="true">
```

or, if it should not be accessible from other apps:

```xml
<activity
    android:name=".InternalActivity"
    android:exported="false">
```

For Android 12 and higher, components with Intent Filters must explicitly specify `android:exported`.

Choose the value based on whether other applications should be able to launch that component.

---

# 21. Handling an Incoming Intent

An Activity launched through an Intent can inspect the incoming Intent.

Example:

```kotlin
class ShareActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        setContentView(R.layout.activity_share)

        val receivedText = intent.getStringExtra(Intent.EXTRA_TEXT)

        Log.d("ShareActivity", "Received: $receivedText")
    }
}
```

---

# 22. Explicit Intent with `ComponentName`

An explicit Intent can also be created using a component:

```kotlin
val intent = Intent().apply {
    component = ComponentName(
        this@MainActivity,
        SecondActivity::class.java
    )
}

startActivity(intent)
```

However, the simpler form is normally preferred:

```kotlin
val intent = Intent(
    this,
    SecondActivity::class.java
)

startActivity(intent)
```

# 23. Starting an Activity with `ActivityResultLauncher`

For modern Android development, use the **Activity Result API** instead of the deprecated `startActivityForResult()` approach.

Example:

```kotlin
private val launcher =
    registerForActivityResult(
        ActivityResultContracts.StartActivityForResult()
    ) { result ->

        if (result.resultCode == Activity.RESULT_OK) {
            val data = result.data

            // Handle result
        }
    }
```

Launch:

```kotlin
val intent = Intent(this, SecondActivity::class.java)

launcher.launch(intent)
```

The Activity Result API works with both your own Activity and suitable external Activity interactions.

# 24. Security Best Practices

### Prefer explicit Intents for your own internal components

```kotlin
Intent(this, SecondActivity::class.java)
```

This avoids relying on system resolution when you know exactly which component should handle the request.

### Be careful with exported components

If another application should not launch an Activity, consider:

```xml
android:exported="false"
```

### Validate incoming Intent data

Do not blindly trust values received from external applications.

Example:

```kotlin
val username = intent.getStringExtra("username")

if (!username.isNullOrBlank()) {
    // Process validated data
}
```

### Use explicit Intents for Services

Android recommends using explicit Intents when starting your own Services because an implicit Service Intent can create security risks.

# 25. Common Intent Actions

| Action | Typical use |
|---|---|
| `ACTION_VIEW` | View/open something |
| `ACTION_SEND` | Share data |
| `ACTION_SENDTO` | Send to a specific communication type |
| `ACTION_DIAL` | Open phone dialer |
| `ACTION_CALL` | Place a call, subject to permissions |
| `ACTION_EDIT` | Edit content |
| `ACTION_MAIN` | Main entry point |
| `ACTION_PICK` | Pick an item |
| `ACTION_GET_CONTENT` | Select content |

Always check the Android documentation for the exact requirements of a specific action.

# 26. Common Mistakes

## Mistake 1: Assuming an implicit Intent always has a handler

This can cause:

```text
ActivityNotFoundException
```

Use:

```kotlin
if (intent.resolveActivity(packageManager) != null) {
    startActivity(intent)
}
```

---

## Mistake 2: Using implicit Intents for internal Activities

If you know the exact Activity, prefer:

```kotlin
Intent(this, SecondActivity::class.java)
```

---

## Mistake 3: Forgetting `CATEGORY_DEFAULT`

When receiving implicit Activity Intents through `startActivity()`, the Intent Filter normally needs:

```xml
<category android:name="android.intent.category.DEFAULT" />
```

---

## Mistake 4: Exposing components unnecessarily

Avoid making an internal component accessible to other applications unless there is a reason.

Use:

```xml
android:exported="false"
```

when appropriate.

# 29. Intent vs Intent Filter

### Intent

The request:

```text
"I want to perform this action."
```

### Intent Filter

The declaration:

```text
"My component can handle this type of action."
```

For example:

```text
App A
  ↓
Implicit Intent
  ↓
Android System
  ↓
Intent Filter Matching
  ↓
App B
```

# 31. Interview Questions

### Q1. What is an Intent?

An Intent is a messaging object used to request an action from another Android application component.

### Q2. What is an Explicit Intent?

An Intent that specifies the exact component to start.

### Q3. What is an Implicit Intent?

An Intent that describes an action without specifying an exact component. Android resolves it using available components and Intent Filters.

### Q4. What is an Intent Filter?

An Intent Filter declares the types of implicit Intents a component can receive.

### Q5. What is the difference between Explicit and Implicit Intent?

Explicit Intents identify a specific component, while implicit Intents describe an action and let Android find a suitable component.

### Q6. Why use `resolveActivity()`?

It checks whether an Activity exists that can handle an implicit Intent before calling `startActivity()`.

### Q7. What is `putExtra()`?

It adds additional data to an Intent.

### Q8. How do you receive Intent extras?

For example:

```kotlin
val name = intent.getStringExtra("name")
```

### Q9. What is `android:exported`?

It controls whether a component can be launched by other applications, subject to Android's component rules.

### Q10. Which Intent should normally be used for your own Service?

Use an explicit Intent.

---

# 32. Key Takeaways

- Intent is a core mechanism for communication between Android components.
- Explicit Intent specifies the exact component.
- Implicit Intent specifies an action and lets Android resolve a suitable component.
- Use `putExtra()` to pass additional data.
- Use Intent Filters to advertise which implicit Intents a component can receive.
- Use `resolveActivity()` before launching an implicit Activity when a handler may not exist.
- Explicitly configure `android:exported` for components with Intent Filters.
- Validate data received from external applications.
- Prefer explicit Intents for your own Services.
- Use the modern Activity Result API for receiving results from Activities.
