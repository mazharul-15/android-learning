# Parcelable in Android Development (Kotlin)

## 1. What is Parcelable?

`Parcelable` is an Android-specific interface used to package (flatten) an object so that it can be passed between Android components through a `Parcel`.

Typical uses:
- Passing a custom object from one Activity to another
- Passing objects through `Intent` extras
- Passing objects through `Bundle`
- Passing data between Android components where Parcelable is supported

Android's `Parcelable` API is designed as a high-performance transport mechanism. It is **not** intended as a general-purpose persistent-storage serialization format.

---

## 2. Parcelable vs Serializable

| Feature | Parcelable | Serializable |
|---|---|---|
| Android-specific | Yes | No |
| Performance | Generally better for Android IPC | Generally slower |
| Boilerplate | High manually, low with `@Parcelize` | Very low |
| Recommended for Android object passing | Yes | Usually not preferred when Parcelable is practical |
| Persistent storage format | No | Not ideal as a long-term format either |

For modern Kotlin Android development, `@Parcelize` is usually the easiest way to implement Parcelable.

---

## 3. Add the Parcelize plugin

In the app-level Gradle Kotlin DSL file:

```kotlin
plugins {
    id("com.android.application")
    id("org.jetbrains.kotlin.android")
    id("kotlin-parcelize")
}
```

The `kotlin-parcelize` plugin generates the Parcelable implementation for you.

---

## 4. Basic @Parcelize Example

```kotlin
import android.os.Parcelable
import kotlinx.parcelize.Parcelize

@Parcelize
data class User(
    val name: String,
    val age: Int,
    val email: String
) : Parcelable
```

That's enough. You do **not** normally need to manually implement:

```kotlin
writeToParcel()
describeContents()
CREATOR
```

The Parcelize compiler plugin generates the required implementation.

---

## 5. Passing an Object from One Activity to Another

### Activity 1

```kotlin
val user = User(
    name = "Mazhar",
    age = 33,
    email = "mazhar@example.com"
)

val intent = Intent(this, SecondActivity::class.java)

intent.putExtra("user", user)

startActivity(intent)
```

### Activity 2

For modern Android APIs, use the type-safe `Intent` overload where available:

```kotlin
val user = intent.getParcelableExtra<User>("user")
```

Then:

```kotlin
user?.let {
    println(it.name)
    println(it.age)
    println(it.email)
}
```

## 6. Why Parcelable is Needed

Suppose you have:

```kotlin
data class User(
    val name: String,
    val age: Int
)
```

You cannot simply assume Android can put this arbitrary object into an Intent.

By implementing Parcelable:

```kotlin
@Parcelize
data class User(
    val name: String,
    val age: Int
) : Parcelable
```

Android gets a representation that can be written to and restored from a `Parcel`.

Conceptually:

```text
User object
    ↓
Parcelable
    ↓
Parcel
    ↓
Intent / Bundle
    ↓
Another Activity
    ↓
User object restored
```

## 7. Passing a List of Parcelable Objects

```kotlin
@Parcelize
data class User(
    val name: String,
    val age: Int
) : Parcelable
```

Create a list:

```kotlin
val users = arrayListOf(
    User("Rahim", 25),
    User("Karim", 28),
    User("Sakib", 30)
)
```

Pass it:

```kotlin
intent.putParcelableArrayListExtra("users", users)
```

Receive it:

```kotlin
val users =
    intent.getParcelableArrayListExtra<User>("users")
```

For newer APIs, prefer the type-safe overloads available in your compile/target SDK.

## 8. Supported Types

`@Parcelize` supports many common types, including:

- Primitive types
- `String`
- `CharSequence`
- Enums
- Other Parcelable classes
- `Bundle`
- Collections such as `List`, `Set`, and `Map`
- Arrays of supported types
- Nullable versions of supported types
- Several Android framework types

Example:

```kotlin
@Parcelize
data class Product(
    val id: Int,
    val name: String,
    val price: Double,
    val tags: List<String>
) : Parcelable
```

---

## 9. Nested Parcelable Objects

```kotlin
@Parcelize
data class Address(
    val city: String,
    val country: String
) : Parcelable

@Parcelize
data class User(
    val name: String,
    val address: Address
) : Parcelable
```

Now `User` can contain another Parcelable object.

---

## 10. Parcelable with Sealed Classes

Parcelize also supports sealed classes.

```kotlin
@Parcelize
sealed class UiEvent : Parcelable {

    @Parcelize
    data class Success(
        val message: String
    ) : UiEvent()

    @Parcelize
    data class Error(
        val message: String
    ) : UiEvent()
}
```

This can be useful when passing structured state/event data.

---

## 11. @IgnoredOnParcel

If a property should not be serialized into the Parcel:

```kotlin
@Parcelize
data class User(
    val name: String,

    @IgnoredOnParcel
    val temporaryValue: String = ""
) : Parcelable
```

`temporaryValue` will not be written to the Parcel.

---

## 12. Manual Parcelable Implementation

Before `@Parcelize`, developers commonly wrote Parcelable manually.

Example:

```kotlin
class User(
    val name: String,
    val age: Int
) : Parcelable {

    private constructor(parcel: Parcel) : this(
        parcel.readString() ?: "",
        parcel.readInt()
    )

    override fun writeToParcel(parcel: Parcel, flags: Int) {
        parcel.writeString(name)
        parcel.writeInt(age)
    }

    override fun describeContents(): Int = 0

    companion object CREATOR : Parcelable.Creator<User> {

        override fun createFromParcel(parcel: Parcel): User {
            return User(parcel)
        }

        override fun newArray(size: Int): Array<User?> {
            return arrayOfNulls(size)
        }
    }
}
```

This works, but it is verbose and easier to get wrong.

For Kotlin Android projects, prefer:

```kotlin
@Parcelize
data class User(
    val name: String,
    val age: Int
) : Parcelable
```

---

## 13. Important Rule

Properties that need to be parcelized should be declared in the primary constructor.

Good:

```kotlin
@Parcelize
data class User(
    val name: String,
    val age: Int
) : Parcelable
```

Be careful with properties declared only in the class body:

```kotlin
@Parcelize
class User(
    val name: String
) : Parcelable {

    val temporaryValue = "Hello"
}
```

`temporaryValue` is not automatically treated like a constructor property for parcelization. Use `@IgnoredOnParcel` where appropriate.

---

## 14. Parcelable is NOT for Large Data

Avoid putting very large objects, huge lists, images, videos, or large byte arrays into an Intent/Bundle.

Example of what to avoid:

```kotlin
intent.putExtra("huge_image", hugeByteArray)
```

Better approach:

```text
Activity A
   ↓
Pass ID / URI / small metadata
   ↓
Activity B
   ↓
Load the actual data from repository/database/file/storage
```

Parcelable is intended for transporting data, not for moving huge datasets between components.

---

## 15. Parcelable is NOT a Database Format

Do not use Parcel as a permanent storage format.

For persistent data, consider:

- Room
- DataStore
- Files
- A backend/database
- Appropriate serialization formats such as JSON when required

Parcelable is primarily useful for Android component communication and transport.

---

## 16. Parcelable in Navigation

Parcelable is commonly useful when a destination needs a small structured object.

However, do not blindly pass large domain objects between screens. Often it is better to pass a small ID:

```text
List Screen
    ↓
productId = 105
    ↓
Details Screen
    ↓
ViewModel
    ↓
Repository
    ↓
Database / API
```

This architecture is generally more scalable than passing the complete object.

---

## 17. Parcelable vs Passing Individual Extras

Without Parcelable:

```kotlin
intent.putExtra("name", user.name)
intent.putExtra("age", user.age)
intent.putExtra("email", user.email)
```

With Parcelable:

```kotlin
intent.putExtra("user", user)
```

Parcelable becomes especially convenient when an object has many related fields.

## 18. Interview Questions

### Q1. What is Parcelable?

`Parcelable` is an Android interface that allows an object to be flattened into a `Parcel` so it can be transported and restored.

### Q2. Why use Parcelable?

It is designed for efficient Android object transport, such as passing data through `Intent` and `Bundle`.

### Q3. What is @Parcelize?

`@Parcelize` is a Kotlin annotation used with the `kotlin-parcelize` plugin to automatically generate Parcelable implementation code.

### Q4. What is CREATOR?

`CREATOR` is the mechanism used by the Parcelable framework to create an object from a Parcel and create arrays of that object.

With `@Parcelize`, you normally do not write it manually.

### Q5. Parcelable vs Serializable?

Parcelable is Android-specific and designed for efficient Android transport. Serializable is Java's general serialization mechanism and is usually slower for Android object transport.

### Q6. Can Parcelable store data permanently?

No. `Parcel`/`Parcelable` should not be treated as a persistent storage format.

### Q7. Can Parcelable pass an image?

Technically some image-related types can be parcelized, but passing large image data through Intent/Bundle is a bad design. Pass a URI/path/ID and load the image separately.

---

## 19. Best Practice for Modern Android

Use:

```kotlin
@Parcelize
data class User(
    val id: Long,
    val name: String,
    val email: String
) : Parcelable
```

Then pass only reasonably small objects:

```kotlin
intent.putExtra("user", user)
```

For large or persistent data:

```text
ID → ViewModel → Repository → Database/API
```

rather than:

```text
Large Object → Intent → Activity
```

## 21. Learning Order

For Android development, learn Parcelable after:

1. Kotlin classes/data classes
2. Intent
3. Bundle
4. Activity-to-Activity data passing
5. Parcelable
6. `@Parcelize`
7. Navigation Component
8. ViewModel + Repository
9. Room/Database

Parcelable is therefore an important Android concept, but you usually do not need to memorize the manual `CREATOR` implementation when using modern Kotlin.
