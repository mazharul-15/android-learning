# Activity Result API in Android Development — Kotlin Notes

## 1. What is the Activity Result API?

The **Activity Result API** is the modern AndroidX approach for starting an activity or requesting something from another component and receiving a result.

Google recommends the Activity Result APIs instead of the older `startActivityForResult()` / `onActivityResult()` approach. The API provides a launcher, a contract describing the input/output types, and a callback for the result.

Official documentation:
https://developer.android.com/training/basics/intents/result

## 2. Main Components

The Activity Result API is based on three important concepts:

### `ActivityResultContract`

Defines:

```text
Input → Activity/operation → Output
```

Examples:

- `GetContent()` → `String` MIME type → `Uri?`
- `RequestPermission()` → permission name → `Boolean`
- `StartActivityForResult()` → `Intent` → `ActivityResult`
- `TakePicture()` → `Uri` → `Boolean`

Android provides many predefined contracts.

### `ActivityResultLauncher`

The launcher starts the operation.

```kotlin
launcher.launch(input)
```

### Callback

The callback receives the result:

```kotlin
registerForActivityResult(contract) { result ->
    // Handle result
}
```

## 3. Basic Flow

```text
1. Create/register a contract
        ↓
2. Get ActivityResultLauncher
        ↓
3. Call launcher.launch(...)
        ↓
4. Another Activity/app performs the operation
        ↓
5. Result is returned
        ↓
6. Callback handles the result
```

## 4. Example: Get Content / Pick an Image

This is one of the most common examples.

```kotlin
import android.net.Uri
import android.os.Bundle
import android.widget.Button
import android.widget.ImageView
import androidx.activity.result.contract.ActivityResultContracts
import androidx.appcompat.app.AppCompatActivity

class MainActivity : AppCompatActivity() {

    private lateinit var imageView: ImageView
    private lateinit var selectButton: Button

    private val getContent =
        registerForActivityResult(ActivityResultContracts.GetContent()) { uri: Uri? ->

            if (uri != null) {
                imageView.setImageURI(uri)
            }
        }

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        setContentView(R.layout.activity_main)

        imageView = findViewById(R.id.imageView)
        selectButton = findViewById(R.id.selectButton)

        selectButton.setOnClickListener {
            getContent.launch("image/*")
        }
    }
}
```

### What happens?

When the button is clicked:

```kotlin
getContent.launch("image/*")
```

Android opens a content picker.

After the user selects an image, the callback receives:

```kotlin
Uri?
```

Then:

```kotlin
imageView.setImageURI(uri)
```

displays the selected image.

## 5. Example: Start Another Activity and Get a Result

Suppose `MainActivity` opens `SecondActivity` and expects a result.

### MainActivity.kt

```kotlin
import android.content.Intent
import android.os.Bundle
import android.widget.Button
import android.widget.Toast
import androidx.activity.result.contract.ActivityResultContracts
import androidx.appcompat.app.AppCompatActivity

class MainActivity : AppCompatActivity() {

    private val secondActivityLauncher =
        registerForActivityResult(
            ActivityResultContracts.StartActivityForResult()
        ) { result ->

            if (result.resultCode == RESULT_OK) {

                val data = result.data
                val message = data?.getStringExtra("message")

                Toast.makeText(
                    this,
                    message ?: "No message",
                    Toast.LENGTH_SHORT
                ).show()
            }
        }

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        setContentView(R.layout.activity_main)

        findViewById<Button>(R.id.openButton).setOnClickListener {

            val intent = Intent(this, SecondActivity::class.java)

            secondActivityLauncher.launch(intent)
        }
    }
}
```

### SecondActivity.kt

```kotlin
import android.content.Intent
import android.os.Bundle
import android.widget.Button
import androidx.appcompat.app.AppCompatActivity

class SecondActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        setContentView(R.layout.activity_second)

        findViewById<Button>(R.id.doneButton).setOnClickListener {

            val resultIntent = Intent().apply {
                putExtra("message", "Hello from SecondActivity")
            }

            setResult(RESULT_OK, resultIntent)
            finish()
        }
    }
}
```

### Flow

```text
MainActivity
     |
     | launch(Intent)
     ↓
SecondActivity
     |
     | setResult(RESULT_OK, intent)
     | finish()
     ↓
MainActivity callback
     |
     ↓
Read result data
```

## 6. Example: Request a Permission

The Activity Result API also provides a contract for runtime permissions.

```kotlin
private val requestCameraPermission =
    registerForActivityResult(
        ActivityResultContracts.RequestPermission()
    ) { isGranted ->

        if (isGranted) {
            // Permission granted
        } else {
            // Permission denied
        }
    }
```

Launch it:

```kotlin
requestCameraPermission.launch(
    android.Manifest.permission.CAMERA
)
```

The callback receives:

```kotlin
Boolean
```

Example:

```kotlin
requestCameraPermission.launch(Manifest.permission.CAMERA)
```

## 7. Example: Request Multiple Permissions

```kotlin
private val requestPermissions =
    registerForActivityResult(
        ActivityResultContracts.RequestMultiplePermissions()
    ) { permissions ->

        val cameraGranted =
            permissions[Manifest.permission.CAMERA] == true

        val locationGranted =
            permissions[Manifest.permission.ACCESS_FINE_LOCATION] == true

        if (cameraGranted && locationGranted) {
            // All required permissions granted
        }
    }
```

Launch:

```kotlin
requestPermissions.launch(
    arrayOf(
        Manifest.permission.CAMERA,
        Manifest.permission.ACCESS_FINE_LOCATION
    )
)
```

The callback returns:

```kotlin
Map<String, Boolean>
```

## 8. Example: Take a Picture

`TakePicture()` saves the captured image into a supplied `Uri` and returns whether the operation succeeded.

```kotlin
private var imageUri: Uri? = null

private val takePicture =
    registerForActivityResult(
        ActivityResultContracts.TakePicture()
    ) { success ->

        if (success) {
            imageView.setImageURI(imageUri)
        }
    }
```

Launch:

```kotlin
imageUri = createImageUri()

takePicture.launch(imageUri)
```

The contract expects:

```text
Input: Uri
Output: Boolean
```

## 11. Why Activity Result API Is Better

The old approach used:

```kotlin
startActivityForResult()
```

and:

```kotlin
onActivityResult()
```

The modern approach uses:

```kotlin
registerForActivityResult()
```

and:

```kotlin
launcher.launch()
```

Advantages include:

- Type-safe contracts.
- Less request-code management.
- Better lifecycle integration.
- Easier permission handling.
- Built-in contracts for common operations.
- Cleaner callbacks.
- Better support for activity/fragment recreation.

## 12. Important Lifecycle Rule

Register the launcher unconditionally.

Recommended:

```kotlin
private val getContent =
    registerForActivityResult(
        ActivityResultContracts.GetContent()
    ) { uri ->
        // Handle result
    }
```

Then launch it later:

```kotlin
getContent.launch("image/*")
```

Do not conditionally register the launcher inside a button click or other conditional logic.

Android's documentation states that `registerForActivityResult()` should be registered every time the Activity/Fragment is created so results can be delivered correctly if the process or Activity is recreated.

## 13. Fragment Example

The API also works with Fragments.

```kotlin
class MyFragment : Fragment(R.layout.fragment_my) {

    private val getContent =
        registerForActivityResult(
            ActivityResultContracts.GetContent()
        ) { uri: Uri? ->

            if (uri != null) {
                // Handle selected content
            }
        }

    override fun onViewCreated(
        view: View,
        savedInstanceState: Bundle?
    ) {
        super.onViewCreated(view, savedInstanceState)

        view.findViewById<Button>(R.id.selectButton)
            .setOnClickListener {

                getContent.launch("image/*")
            }
    }
}
```

## 14. Common ActivityResultContracts

| Contract | Input | Output |
|---|---|---|
| `GetContent()` | MIME type `String` | `Uri?` |
| `OpenDocument()` | MIME type array | `Uri?` |
| `CreateDocument()` | File name | `Uri?` |
| `GetMultipleContents()` | MIME type `String` | `List<Uri>` |
| `RequestPermission()` | Permission `String` | `Boolean` |
| `RequestMultiplePermissions()` | Array of permissions | `Map<String, Boolean>` |
| `TakePicture()` | `Uri` | `Boolean` |
| `TakePicturePreview()` | No meaningful input | `Bitmap?` |
| `StartActivityForResult()` | `Intent` | `ActivityResult` |

## 15. Custom ActivityResultContract

You can create your own contract when the predefined contracts don't fit your requirement.

```kotlin
class MyContract :
    ActivityResultContract<String, String>() {

    override fun createIntent(
        context: Context,
        input: String
    ): Intent {
        return Intent(context, SecondActivity::class.java)
            .putExtra("input", input)
    }

    override fun parseResult(
        resultCode: Int,
        intent: Intent?
    ): String {
        return intent?.getStringExtra("result")
            ?: ""
    }
}
```

Register it:

```kotlin
private val myLauncher =
    registerForActivityResult(MyContract()) { result ->

        // Handle result
    }
```

Launch it:

```kotlin
myLauncher.launch("Hello")
```

The generic types show the contract's input and output:

```kotlin
ActivityResultContract<Input, Output>
```

## 16. ActivityResult API vs onActivityResult

| Old API | Activity Result API |
|---|---|
| `startActivityForResult()` | `launcher.launch()` |
| `onActivityResult()` | Callback |
| Request codes | Contracts |
| More manual handling | Type-safe |
| Legacy approach | Recommended modern approach |

## 17. Common Mistakes

### Mistake 1: Registering inside a click listener

Avoid:

```kotlin
button.setOnClickListener {

    val launcher =
        registerForActivityResult(...) {
            // ...
        }

    launcher.launch(...)
}
```

Register once during initialization, then call `launch()` when needed.

### Mistake 2: Launching before the Activity/Fragment is ready

The launcher should be launched only after the appropriate lifecycle state has been reached.

### Mistake 3: Assuming a result is always available

For contracts returning nullable values such as `Uri?`:

```kotlin
if (uri != null) {
    // Use URI
}
```

Always handle cancellation/no-result cases.

### Mistake 4: Keeping important transient state only in local variables

The Activity/process may be destroyed while another activity is running. State needed to correctly handle the result should be saved/restored separately when necessary.

## 19. Key Takeaways

1. Activity Result API is the modern way to receive results from activities and other contracts.
2. Use `registerForActivityResult()` to register a callback.
3. Use `ActivityResultContracts` to define common operations.
4. Use `ActivityResultLauncher.launch()` to start the operation.
5. Results are delivered through the callback.
6. The API is lifecycle-aware.
7. Register launchers unconditionally.
8. Built-in contracts support content selection, documents, permissions, camera operations, and more.
9. Custom contracts can be created for application-specific workflows.
10. Prefer Activity Result APIs over legacy `startActivityForResult()` / `onActivityResult()`.
