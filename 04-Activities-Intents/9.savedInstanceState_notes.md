# savedInstanceState in Android

## 1. What is savedInstanceState?

`savedInstanceState` is a `Bundle` that Android can provide when an Activity is recreated.

It is mainly used to preserve **temporary UI/state information**, such as after a configuration change like screen rotation.

It is NOT a replacement for a database.

---

## 2. Who calls onSaveInstanceState()?

**Android calls it automatically.**

You normally do not call:

```kotlin
onSaveInstanceState()
```

yourself.

Example:

```kotlin
override fun onSaveInstanceState(outState: Bundle) {
    super.onSaveInstanceState(outState)
}
```

Android decides when this callback is needed.

---

## 3. Who provides savedInstanceState?

Android provides the `Bundle` to `onCreate()`.

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
}
```

You do not normally create `savedInstanceState` yourself.

It can be:

```kotlin
savedInstanceState == null
```

when there is no previously saved state, or non-null when Android has state to restore.

---

## 4. Basic flow

```text
User enters data
       ↓
Activity is running
       ↓
Screen rotates
       ↓
Android calls onSaveInstanceState()
       ↓
You put temporary state into Bundle
       ↓
Old Activity is destroyed
       ↓
New Activity is created
       ↓
Android passes Bundle to onCreate()
       ↓
onCreate(savedInstanceState)
       ↓
Restore the state
```

Remember:

> Android calls → save into Bundle → Activity recreated → Android gives Bundle back → restore.

---

# 5. Bundle

A `Bundle` is a container for small pieces of state.

For example:

```kotlin
outState.putString("name", "Mazharul")
outState.putInt("age", 25)
```

Later:

```kotlin
val name = savedInstanceState?.getString("name")
val age = savedInstanceState?.getInt("age")
```

The key must match:

```text
"name" → "name"
"age"  → "age"
```

---

# 6. Student Information Example

Suppose the app has:

```text
Student Information

Name       [Mazharul]
Age        [25]
Student ID [123]
Department [CSE]

          [SAVE]
```

The student has entered the information but has NOT pressed the Save button.

The phone is rotated.

## Save state

```kotlin
override fun onSaveInstanceState(outState: Bundle) {

    outState.putString(
        "name",
        etName.text.toString()
    )

    outState.putString(
        "age",
        etAge.text.toString()
    )

    outState.putString(
        "student_id",
        etStudentId.text.toString()
    )

    outState.putString(
        "department",
        etDepartment.text.toString()
    )

    super.onSaveInstanceState(outState)
}
```

Android calls this method.

You don't call it.

---

## Restore state

Android creates the Activity again and passes the Bundle:

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    setContentView(R.layout.activity_main)

    if (savedInstanceState != null) {

        etName.setText(
            savedInstanceState.getString("name")
        )

        etAge.setText(
            savedInstanceState.getString("age")
        )

        etStudentId.setText(
            savedInstanceState.getString("student_id")
        )

        etDepartment.setText(
            savedInstanceState.getString("department")
        )
    }
}
```

After rotation, the user can see:

```text
Name       → Mazharul
Age        → 25
Student ID → 123
Department → CSE
```

# 7. SAVE button vs savedInstanceState

These are different concepts.

## SAVE button

The user's action:

```text
[SAVE]
   ↓
Save student
   ↓
Database / persistent storage
```

This is for keeping the student's information as application data.

## savedInstanceState

Android lifecycle mechanism:

```text
Rotation
   ↓
Activity recreation
   ↓
Preserve temporary state
```

It is not permanent storage.

### Easy rule

> `SAVE` means "save my student."

> `savedInstanceState` means "help restore my screen after Activity recreation."

---

# 8. Do I always need to implement it?

**No.**

You do not need to add `onSaveInstanceState()` to every Activity.

Normal Android Views, such as `EditText`, can save and restore much of their own view state automatically when they have proper IDs.

For learning, manually saving the fields is useful because it makes the lifecycle flow easy to understand.

---

# 9. What is Activity recreation?

Rotation can cause:

```text
Old Activity
     ↓
destroyed
     ↓
New Activity
```

The new Activity is a new object.

Therefore, ordinary Activity member variables can be lost:

```kotlin
var studentName = ""
```

If you need a small piece of temporary state to survive recreation, `savedInstanceState` can be used.

---

# 10. Important limitation

`savedInstanceState` is for **small temporary state**, not large or permanent data.

Do NOT think of it as:

```text
Database
```

Think of it as:

```text
Temporary state needed to recreate the UI
```

For permanent student information, use appropriate persistent storage such as Room/database, depending on the project.

---

# 11. Most important code to remember

### Save

```kotlin
override fun onSaveInstanceState(outState: Bundle) {
    outState.putString("name", studentName)
    super.onSaveInstanceState(outState)
}
```

### Restore

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)

    val name = savedInstanceState?.getString("name")
}
```

---

# 12. Three questions to remember

### Q1. Who calls onSaveInstanceState()?

**Android.**

### Q2. Who creates/provides savedInstanceState?

**Android provides the Bundle to your Activity.**

### Q3. Do I manually call these?

**Normally, no.**

You only override the callback when you need to save custom temporary state.
